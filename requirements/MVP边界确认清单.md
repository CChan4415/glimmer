## ⚠️ 方向更新（2026-08-12，已定稿，最高优先级）

需求对话后，第一版范围已重新收敛。**第一版边界已冻结**，完整决策见 [产品决策记录.md](产品决策记录.md)：

- **第一版 = 关系资产管理 + 可视化 + 2 度被动浏览**：
  1. 注册登录（手机号 + 微信 + Apple）
  2. 移动端一键导入通讯录
  3. 生成精美关系图（通讯录分组着色：家人 / 同事 / 朋友）
  4. 编辑修正
  5. 关系资产统计（简单统计，无 AI）
  6. **看到朋友的朋友**（被动浏览：点开朋友节点看 2 度，未注册默认化名）
  7. 隐私控制（双向全局开关：对他人 + 对自己）
  8. Web 看图（同账号，只展示，不导入）
- **第二版**：关系发现（主动搜索）+ 引荐请求 + AI 打标/顾问 + 3 度 + 失联提醒 + 推送 + 机会市场 + 商业化 + 认领流程完善。
- 隐私原则：真名私有，化名是公开形象；未注册默认化名；认领机制（决策 #04）。
- 本节下方 §1–§3 的"主动搜索 / 引荐 / 通知"相关条目，一律视为第二版内容，不再作为第一版边界。

## 0. 冻结原则

1. **结果导向**：用户要的是结果（对象 / 朋友 / 同好 / 机会），关系图只是引擎。MVP 的任何功能必须直接服务"发现机会 → 发起引荐"这条主链路。
2. **单机也有价值**：即使朋友没来，用户录入联系人后也能获得价值（关系资产统计）。
3. **隐私默认**：默认匿名、永远匿名；任何功能不得默认暴露他人身份。
4. **可交付**：每个功能有明确的输入 / 输出，能写验收标准。
5. 灰色地带默认取"最小实现"，不接 AI、不做推送、不做图谱可视化——这些留给 P1/P2（见 §4）。

## 1. MVP 做什么（冻结清单）

按用户旅程，MVP 完整闭环：**注册 → 录入联系人 → 看首页机会 → 关系发现 → 发起引荐**。

### 1.1 注册 / 登录（P0）

| 项 | 内容 |
| --- | --- |
| 登录方式 | 不用手机号。Apple ID + Google + 邮箱（三选一） |
| 首屏文案 | "欢迎来到你的关系空间，这里只有你能看见你的关系图谱" |
| 隐私承诺 | 注册流程中明确展示：默认匿名、关系图仅自己可见 |
| 边界 | 不做：通讯录授权、邀请好友流程（冷启动话术放 P1） |

### 1.2 建立关系网（P0）

- 手动添加联系人，字段：姓名、关系类型（同学 / 同事 / 家人 / 兴趣同好）、认识时间、最近联系时间、兴趣标签（可多选）。
- 兴趣标签：预设标签库 + 自定义新增。预设参考：骑行、摄影、动漫、旅游、投资、创业、羽毛球、AI、设计师、金融……
- 联系人列表 / 详情页：可编辑、可删除。
- **录入后即展示"关系资产统计"**：按标签聚合计数（"创业者 8 / 程序员 5 / 摄影师 3"），作为冷启动价值。
- 边界：不做通讯录导入（P1）、不做 AI 自动打标签（P1）。

### 1.3 首页：今日关系机会（P0）

首页不放关系图，放机会卡片，两类进 MVP：

- 失联提醒："你已经 180 天没联系张三（标签：产品）"
- 关系资产概览："你的人脉里有：创业者 8 / 程序员 5 / 投资人 1"

（另两类依赖二度网络动态与位置数据，见 §3 D5，默认不进 MVP）

### 1.4 关系发现（P0）

- 入口：搜索框 + 标签选择器（"我想认识____的人"）。
- 输入：一个或多个兴趣 / 角色标签（AND 组合）。
- 输出：按关系距离分组——1 度 N 人 / 2 度 N 人 / 3 度 N 人。
- **匿名展示**：2 度及以上人物只显示"某摄影师 / 某创业者 / 某律师"，不显示姓名；1 度人物因是本人录入，显示真实信息。
- 每个匿名结果显示最短路径中间人（"通过 王五 认识"），但中间人不可直接看到目标身份以外的信息。
- 边界：不做自然语言理解（AI，P2）、不做全网搜索（机会市场，P2）。

### 1.5 引荐请求（P0）

- 用户在发现结果中点击"介绍给我" → 选择（或系统推荐）中间人路径 → 发起请求。
- 中间人收到："张三 想认识你的摄影师朋友"，可 同意 / 拒绝 / 忽略。
- 同意：建立 A 与目标的连接，目标身份对 A 解锁（双方各自动加为联系人？见 §3 D7）。
- 拒绝 / 忽略：A 收到"对方暂未同意"，不知道中间人拒绝还是目标不愿（隐私保护）。
- 边界：不做站内聊天（明确不做）、不做推送（站内通知轮询，P1 再接推送）。

## 2. MVP 明确不做（冻结）

| # | 不做 | 级别 | 说明 |
| --- | --- | --- | --- |
| 1 | 聊天 / 私信 | 永久不做 | 与微信 / WhatsApp 正面竞争的领域 |
| 2 | 发动态 / 朋友圈 / 点赞评论 | 永久不做 | 内容驱动赛道已饱和 |
| 3 | 通讯录导入 | P1 | 先手动、后导入，降低敏感度 |
| 4 | AI 自动打标签 | P1 | 手动标签起步 |
| 5 | AI 关系顾问 / 自然语言问答 | P1→P2 | 留好 API 接口，后接 |
| 6 | 关系图谱可视化 | P1 | 第二层入口，MVP 以列表 / 统计呈现 |
| 7 | 推送通知 | P1 | MVP 用站内通知（轮询） |
| 8 | 机会市场（发布需求 / 服务收费） | P2 | 商业模式第三阶段 |
| 9 | 会员 / 订阅 / 支付 | P2 | MVP 全部免费 |
| 10 | 位置 / 地理数据 | P2 | 首页"来到新加坡"类依赖 |

## 3. 灰色地带决策点（【需决策】）

以下每个点需要你拍板。推荐默认值已填，你只需"同意"或给出修改。

| # | 决策点 | 背景 / 为什么需要拍板 | 推荐默认值 |
| --- | --- | --- | --- |
| **D1** | 录入联系人后的"关系分析报告" | 对话总结里两处表述：冷启动"录入 20 人生成报告（创业者 8…）"；功能地图"录入 10 人后展示价值统计"。是简单统计还是 AI 生成？ | **简单统计**：按用户手动打的标签聚合计数，不接 AI。成本极低、即时可测，AI 版放 P1 |
| **D2** | MVP 引荐通知方式 | 技术选型：推送 P1，站内通知先顶替 | **站内通知 + 轮询**：引荐请求出现在"通知"Tab，不做 APNs/FCM |
| **D3** | 关系强度怎么定义 | 首页有"180 天没联系张三"，但功能地图把"关系圈层 / 强度分析"标为 P1 | **MVP 只做"最近联系时间"字段**（用户手动维护），失联提醒 = 距今天数 > 90 天；不做亲密度打分算法（P1） |
| **D4** | 四层可见性在 MVP 的落地范围 | 对话定义了 L1 私人 / L2 匿名共享 / L3 半公开 / L4 授权公开。MVP 是否完整实现？ | **MVP 落地 L1 + L2 + 授权解锁**：本人录入关系默认 L1 仅自己可见；进入关系发现时按标签暴露为"某摄影师"（L2 匿名）；引荐成功后解锁真实身份（授权解锁）。L3 半公开、L4 授权公开的管理界面进 P1，但数据库 schema 一次性按四层设计 |
| **D5** | 首页"今日关系机会"四类全做还是简化 | 四类里两类依赖二度网络动态 / 位置数据，冷启动阶段无数据可展示 | **MVP 只做两类**：失联提醒 + 关系资产概览。另两类（"新增 3 位 AI 创业者"、"2 位朋友来到新加坡"）进 P1 |
| **D6** | 关系发现的搜索能力边界 | 对话举例含"我想认识摄影爱好者"（标签）与"找律师"（角色）。是否支持自然语言？ | **结构化标签搜索**：兴趣 / 角色标签多选（AND 组合），结果按距离分组。不做自然语言理解（AI，P2）；"找律师"通过"律师"角色标签实现 |
| **D7** | 引荐的完整闭环规则 | 同意后"建立连接"具体指什么？中间人、目标、请求方的角色边界需明确 | **同意后：目标身份对 A 解锁 + A 与目标自动互为 1 度联系人（各占一个联系人位，由双方各自确认增补）**；中间人全程只做传话，不进入 A 的关系图 |
| **D8** | 引荐超时与防骚扰规则 | 功能地图未定义：超时未回复怎么办？能否重复引荐同一人？ | **超时 7 天自动关闭**，请求方收到"已超时"；对同一目标：中间人拒绝后 30 天内不得重发；同一目标最多被请求 3 次 / 月（防骚扰） |
| **D9** | 关系发现的最低门槛 | 用户只录 1 个联系人就开放发现，结果全是 0，体验差 | **1 度联系人 ≥ 5 人才开放"关系发现"入口**；未达门槛时引导继续录入并展示已录资产统计 |
| **D10** | MVP 首版语言与上架区域 | 产品定位偏国际（新加坡冷启动），但用户对话为中文 | **首版英文 UI**（定位新加坡创业者 / 国际用户），上架 App Store + Google Play；中文 UI 和大陆发行后置。登录方式因 App Store 政策：Apple 登录必选 |
