# P0 交互细节 — Glimmer / 流萤（第一版）

> 状态：**初稿（待拍板）** · 2026-08-12
> 前置依据：[产品决策记录.md](产品决策记录.md)（#02/#05/#06/#07/#08）· [用户故事与验收标准.md](用户故事与验收标准.md)
> 范围：第一版核心功能的输入/输出、边界情况、异常流。**聚焦两个体验最重的功能：导入通讯录、关系图与 2 度浏览**；登录与隐私设置为次要，只列关键异常。
> 编写方式：每个功能含触发 → 主流程 → 边界/异常流 → 展示层要求；【需决策】点已标出并给推荐默认值。

## 1. 导入通讯录（核心）

### 1.1 触发与入口

- 入口：新用户引导后首屏主按钮"导入通讯录"；老用户在"设置→同步"或首屏均可再次进入。
- 已有数据时再次导入：走 1.4 增量逻辑，不重复全量。

### 1.2 主流程

1. 点击"导入通讯录" → 弹出**权限用途说明**（弹层）："用于在你的关系图中建立联系人，仅你可见；你的联系人被朋友看到时使用化名。" → 点击"同意"才调起系统通讯录权限。
2. 系统权限：**允许** → 本地读取通讯录；**拒绝** → 走 1.3 异常流。
3. 本地解析：姓名 + 电话 + 通讯录分组（家人/同事/朋友）。仅手机号≥1 条、有姓名的条目进入候选；无姓名或纯邮箱联系人不导入（见 D-1）。
4. **去重**：相同手机号合并；相同手机号但不同名 → 保留一条，标"可能重复"，可手动改。
5. 上传云端（受"同步我的关系"开关控制，见 [用户故事 US-B1/D-B1](用户故事与验收标准.md)）：上传的联系人数据用于服务端匹配"朋友的朋友"，上传内容=姓名 + 化名标识 + 分组 + 手机号哈希，**不包含完整手机号原文**（隐私最小化，见 D-2）。
6. 完成页：显示"导入 N 人 · 家人 X / 同事 Y / 朋友 Z"，主行动按钮"生成我的关系图"。

### 1.3 异常流

| 异常 | 行为 |
| --- | --- |
| 权限拒绝 | 不卡流程。展示"未授权通讯录，可手动添加联系人"空态；提供"去设置开启"入口（iOS 跳系统设置）。不反复弹窗强索。 |
| 权限已授予但系统通讯录为空 | 提示"通讯录为空"，引导手动添加。 |
| 网络中断（上传阶段） | 本地解析已完成 → 本地暂存，提示"已解析 N 人，同步暂未完成"，重试按钮；不丢失已解析数据。 |
| 上传中途退出 App | 下次打开提醒"上次导入未完成，继续同步？"；支持断点续传（按批次上传）。 |
| 联系人含特殊字符 / 超长姓名 | 截断展示（姓名上限 N 字，超长省略号）；不阻断导入。 |
| 导入量巨大（如 5000+） | 分批解析，进度条；完成页展示"共导入 N 人，其中 M 人无电话已跳过"。 |

### 1.4 再次导入（增量）

- 已存在联系人：按手机号匹配，更新分组/姓名（不新增重复）。
- 新增联系人：追加；删除的联系人：提示"有 X 个联系人在通讯录中已不存在，保留为手动联系人？"→ 默认保留（用户手动维护过的关系不因通讯录变动而消失，见 D-3）。

**【需决策】D-1：导入过滤规则**
- **决定（2026-08-12）**：有姓名即导入。导入方式=**A（手机通讯录，主）+ B（手动批量添加，表格式）+ C（单人手动词条添加）**。未来若发现其他批量来源（如 Google 通讯录 OAuth）作为 D 补入后续版本。手机通讯录是唯一可行的批量导入来源——微信/QQ/Facebook/LINE/WhatsApp/Telegram 均不向第三方开放好友列表 API，这是全行业的隐私趋势，不是技术限制。
- 备注：有姓名的条目加入候选；无姓名 + 仅电话的联系人自动填充姓名为"未知联系人"（可后续编辑）；纯邮箱的跳过。

**【需决策】D-2：上传数据最小化**
- 推荐默认：**上传手机号哈希（非明文）+ 姓名 + 分组**；明文手机号仅存本地。服务端只存哈希，用于匹配。
- 备选：明文上传（服务端存明文手机号，检索快但隐私风险高）。
- 合规影响：PIPL 下通讯录第三方数据需单独同意；哈希化降低风险面（详细在非功能需求文档展开）。

**【需决策】D-3：联系人保留策略**
- 推荐默认：**通讯录中已删除的联系人，在关系图中默认保留为手动联系人**（用户手动维护的资产不因通讯录变动丢失）。
- 备选：跟随通讯录删除（简洁，但破坏用户手动维护的数据）。

## 2. 关系图（核心）

### 2.1 触发与主流程

- 入口：导入完成页"生成我的关系图" / 底部 Tab"关系图"。
- 首屏：**中心 = 我**，1 度联系人为第一圈，按分组着色（家人/同事/朋友）。
- 交互：缩放（捏合/滚轮）、拖拽、点节点看详情（见 2.4）。
- 未达 2 度门槛（[US-D2](用户故事与验收标准.md)：≥1 个已注册授权联系人）时，图只显示 1 度，不出现"朋友的朋友"提示入口。

### 2.2 图布局与渲染要求

- 力导向布局（引力/斥力模拟）；2000 节点本地生成 ≤ 3s。
- 节点样式：圆形，大小随分组固定；家人/同事/朋友三色；**已注册授权联系人**显示小标识（示意"可展开"）。
- 连线：1 度连线 = 实线；2 度连线（到朋友的朋友）= 虚线（视觉区分）。
- 可缩放至单节点；聚合：1 度 >30 人时按分组聚合显示（如"同事 42"节点），点开展开（D-4）。

### 2.3 边界 / 异常流

| 场景 | 行为 |
| --- | --- |
| 通讯录为 0 | 关系图空态：插画 + "导入通讯录"主按钮 + "手动添加"次按钮。 |
| 全部联系人无分组 | 全部归入"朋友"默认组（D-5）。 |
| 联系人太多导致渲染卡顿 | 分批渲染 + 惰性展开（只渲染视口内 + 聚合）；降级提示"图较大，已按分组折叠"。 |
| 2 度好友未授权 | 节点显示化名（姓氏+称呼/昵称），**点击不可进入其 2 度**（3 度属第二版）。 |
| 断网加载图 | 有本地缓存则显示缓存 + "离线"标记；无缓存显示重试。 |
| 图节点被误点 | 节点详情可关闭（点空白处/关闭按钮）；删除/编辑均需确认（见 2.4）。 |

### 2.4 节点详情 / 编辑

- 点节点 → 底部弹出详情卡：
  - **1 度联系人**：姓名、电话、分组、标签、最近联系时间；操作：编辑 / 删除（二次确认）。
  - **2 度联系人**：化名、分组（仅当对方设置"化名+分组"时显示）；无编辑/删除权限（非本人数据）。
- 编辑弹层字段：姓名、分组（可改）、标签（预设+自定义）、电话（可改）、最近联系时间（可改）。
- 删除联系人：确认弹层"删除后将从你的关系图中移除，是否继续？"。

**【需决策】D-4：聚合规则**
- **决定（2026-08-12）**：第一版不做分组聚合；但单个分组 >100 人时提示"图较大，建议按分组筛选查看"。聚合、筛选等分组管理细节留给第二版。第二版接入 AI 自动分组后分组数量激增，届时再定聚合策略。
- 备注：AI 自动分组不进第一版（决策 #03，改为第二版内容），第一版分组来源仅通讯录自带分组 + 手动标签，自然规模小。

**【需决策】D-5：无分组默认组**
- **决定（2026-08-12）**：未分发联系人默认归入"未分组"独立分组，不做"朋友"兜底。
- 备选（已否决）：默认归入"朋友"组——用户明确不需要。

## 3. 2 度浏览（朋友的朋友）（核心）

### 3.1 触发与主流程

- 1 度节点上出现"可展开"标识（已注册且授权）→ 点击节点 → 卡片中"查看 TA 的朋友"→ 展开该联系人的朋友（2 度）。
- 2 度列表内联展开在图中（或底部卡片列表视图），显示：化名、分组（若对方允许）、与中间人的关系（无）。
- 展示为**二级缩进**，不进入 3 度（第二版）。

### 3.2 边界 / 异常流

| 场景 | 行为 |
| --- | --- |
| 该联系人有朋友但全部未授权/未注册 | 显示"TA 的朋友暂未公开"（不显示任何名字）。 |
| 该联系人本身化名 | 正常显示其 2 度（2 度人物仍按各自授权展示）。 |
| 2 度人物与我有共同好友（冗余路径） | 只显示一次；若出现在多条 2 度路径，标注"你们有 X 位共同好友"。 |
| 朋友关系被对方关闭（设置里"我不出现"） | 该联系人从"可展开"变为不可展开；已缓存的立即失效。 |
| 我关闭"我的联系人可被看到" | 我的联系人从所有朋友视图消失；图内 2 度部分隐藏。 |

### 3.3 隐私联动

- 展示严格受 [US-E1/US-E2](用户故事与验收标准.md) 双向开关约束：任何一边关闭即不可见。
- 2 度人物**永远不显示手机号**；仅化名 + 可选分组。

## 4. 登录 / 隐私设置（次要，关键异常）

| 功能 | 关键异常 |
| --- | --- |
| 手机号登录 | 验证码错误 5 次锁定 10 分钟；60s 重发间隔；有效期 5 分钟。 |
| 微信/Apple 登录 | 授权失败 → 回退到手机号登录；不丢失已登录会话。 |
| 账号绑定 | 已用手机号登录后绑微信：确认弹层"将合并到当前账号？"（D-6）。 |
| 隐私开关切换 | 切换后**即时生效**，不要求重新登录；切换"我的联系人可被看到"为关 → 弹出说明"你的联系人将从朋友的网络中移除"。 |
| 删除账号 | 30 天冷静期；冷静期内可撤销；到期彻底删除（含云端哈希数据）。 |

**【需决策】D-6：绑定冲突处理**
- **决定（2026-08-12）**：手机号为主账号，微信/Apple 绑定到该账号；冲突时提示解绑/选主账号。
