## 1. 注册 / 登录（US-A）

### US-A1：新用户注册（手机号）

> 作为新用户，我想用手机号注册，以便快速开始使用。

**验收标准**
- 输入手机号 → 获取验证码（60s 倒计时，可重发，间隔 ≥ 60s）→ 输入验证码 → 登录成功。
- 验证码有效期 5 分钟；错误验证码给出明确提示，错误 N 次后锁定（见 D-A2）。
- 首次注册进入引导流程（US-A4），老用户直接进入首页。
- 登录态持久化；App 冷启动自动恢复登录，失效时静默跳回登录页。

### US-A2：微信登录 / Apple 登录

> 作为用户，我想用微信或 Apple 直接登录，省去输手机号。

**验收标准**
- 微信 OAuth、Apple Sign-In 均可用；成功 → 走 US-A4 引导（新）/ 首页（老）。
- 微信 / Apple / 手机号三种方式**可绑定同一账号**（见 D-A1），任一方式登录后可看到同一份数据。

### US-A3：退出登录 / 账号找回

> 作为用户，我想退出登录或找回账号。

**验收标准**
- 退出登录后回到登录页；重新登录（任一方式）恢复数据。
- 同一手机号重复注册：提示"该手机号已注册，请直接登录"，引导登录而非覆盖。

### US-A4：首次进入引导

> 作为新用户，我第一次打开 App，想知道这是什么、安不安全。

**验收标准**
- 3-5 屏引导：产品是什么（发现身边的关系机会）→ **隐私承诺（你的关系图只有你能看，朋友看到的是化名）** → 权限说明（通讯录导入是主动的、可拒绝）。
- 引导全程可跳过，可"同意并开始"。
- 引导文案体现决策 #04 的隐私原则。

**【需决策】D-A1：账号绑定粒度**
- 背景：三种登录方式如何关联。
- 推荐默认：**同一手机号绑定微信后，两种方式登录同一账号**；Apple 若绑定同一手机号也归并。实现上以手机号为账号主键，微信/Apple 为绑定渠道。
- 备选：三种方式独立账号（不做归并）——简单，但用户换方式登录会看到空数据。

**【需决策】D-A2：验证码错误策略**
- 推荐默认：连续错 5 次锁定 10 分钟；单日每号码上限 20 条。
- 备选：不锁定（简单，但易被刷）。

## 2. 导入通讯录（US-B）

### US-B1：一键导入通讯录

> 作为用户，我想一键导入手机通讯录，快速建立关系网。

**验收标准**
- 首页/入口提供"导入通讯录"主按钮，点击后请求通讯录权限（**先说明用途，再请求**）。
- 授权后：导入姓名 + 电话号码 + 通讯录分组（家人 / 同事 / 朋友）。
- **本地解析、本地匹配、仅已授权数据上传**（PIPL 合规：处理通讯录第三方数据需单独同意，见 D-B1）。
- 导入失败（权限拒绝 / 网络中断）给出可重试提示，不卡死流程。
- 导入完成页：展示导入人数 + 分组统计，提供"开始生成关系图"主行动。

**【需决策】D-B1：通讯录数据上云边界**
- 推荐默认：**导入后数据存云端**（关系图、朋友的朋友依赖服务端比对）；但**仅在"同步我的关系"开关开启时**才把联系人数据用于匹配，隐私设置里可关（见 US-F）。
- 备选：本地优先（不上云），但"朋友的朋友"无法实现——**与决策 #06 冲突，不建议**。
- 合规红线：授权通讯录权限 ≠ 可任意处理第三方数据；需"单独同意"+ 说明用途（PIPL 第九条）。此条纳入非功能需求文档。

### US-B2：导入后去重 / 合并

> 作为用户，我想让重复的联系人自动合并，而不是看到一堆重复人。

**验收标准**
- 相同电话号码的去重合并；姓名相似但号码不同 → 保留两个，提示用户手动合并（见 US-C1）。
- 去重规则在数据模型设计时明确（号码为主，姓名为辅）。

## 3. 生成与查看关系图（US-C）

### US-C1：生成精美关系图

> 作为用户，我想看到一张按我导入的联系人自动生成的关系图。

**验收标准**
- 导入完成即生成；中心是自己，1 度联系人为第一圈。
- **按通讯录分组着色**：家人 / 同事 / 朋友各有颜色（分组配色在 UI 阶段定）。
- 图支持：缩放、拖拽、点开联系人节点看详情。
- 生成耗时 ≤ 3s（本地 2000 联系人量级，见 D-C1）。
- **可在图上直接编辑**：改分组、改名字、删除联系人（对图中节点操作）。

### US-C2：联系人详情与编辑

> 作为用户，我想查看和编辑单个联系人信息。

**验收标准**
- 点开节点显示：姓名、电话、分组、标签、最近联系时间（若有）。
- 可编辑：姓名、分组、标签（预设 + 自定义新增）、电话、最近联系时间。
- 可删除联系人；删除需确认（避免误删）。
- 手动新增联系人（不通过导入）也支持，字段同上。

### US-C3：关系资产统计

> 作为用户，我想看到我的关系资产全景。

**验收标准**
- 统计页（或图上角标）：按分组聚合——"家人 N / 同事 N / 朋友 N"，以及自定义标签聚合。
- 统计随编辑实时更新；为纯客户端计算或服务端简单计数（无 AI）。

**【需决策】D-C1：关系图渲染引擎**
- 推荐默认：**Web 端用成熟图库**（如 d3-force 力导向图，或 Cytoscape/vis-network）；**移动端第一版用轻量列表 + 简单图**（Flutter 图库如 graphview 先评估），精美 3D / 大图交互放 Web。
- 备选：两端都做重图交互——成本高，第一版不建议。
- 说明：这是"关系图是第一版核心"的关键技术点，但属设计阶段决策，这里先标出。

## 4. 看到朋友的朋友（2 度被动浏览）（US-D）

### US-D1：浏览朋友的朋友

> 作为用户，我想在看自己关系图时，展开看到朋友的朋友。

**验收标准**
- 点开一个**已在平台注册且授权**的朋友节点 → 展开显示他的朋友（2 度），**缩进/二级展示**在图上。
- **未注册 / 未授权**的联系人：显示为**化名**（默认昵称规则见 D-D1），**不显示真实姓名**（决策 #04）。
- 2 度人物可点开看化名 / 分组信息，但**看不到对方手机号等私密字段**。
- **只有"我的联系人"和"朋友的朋友"两层**，不展示 3 度（第二版）。
- 未达门槛（D-D2）时显示引导，不硬展示空态。

### US-D2：我出现在朋友的网络里

> 作为用户，我的朋友能看到我，我想知道别人看到我什么。

**验收标准**
- 我的信息以**化名**出现在朋友的 2 度网络中（默认），符合决策 #07 默认"仅化名"。
- 我的展示级别由我自己的隐私设置控制（US-F2），变化实时生效。

**【需决策】D-D1：化名默认规则**
- 推荐默认：**默认化名 = 姓氏 + 通用称呼**（如"陈先生 / 王小姐"），或**昵称**（用户可设置自己的昵称，默认"我"）。姓名完整隐藏。
- 备选：默认显示真实姓名——与决策 #04 冲突，不建议。
- 具体规则（姓氏 + 称呼 / 昵称）在 UI 阶段定稿。

**【需决策】D-D2：2 度功能开放门槛**
- 推荐默认：**至少 1 个联系人已注册并授权**才显示"朋友的朋友"入口；否则引导"邀请朋友"。
- 备选：不做门槛，直接显示"还没有可展示的朋友的朋友"。

## 5. 隐私设置（US-E / US-F）

### US-E1：控制"我的数据"对他人可见性（全局开关）

> 作为用户，我想控制我导入的联系人是否被朋友的朋友看到。

**验收标准**
- 设置页有全局开关："**我的联系人可被朋友的朋友看到**"，默认开。
- 关闭后：我的联系人不再出现在任何朋友的朋友视图中；已展示的立即失效。
- 开关说明文案体现"展示关系的存在，不暴露身份"。

### US-E2：控制"我"在他人的网络中的展示

> 作为用户，我想控制别人看到我什么。

**验收标准**
- 设置页第二个开关："**我是否出现在朋友的网络中**"，默认开。
- 展示级别两档：**仅化名（默认）/ 化名 + 分组**（即朋友看到我的名字时可附带看到"同事"分组，但不显示具体是谁的同事）。
- 展示范围实时生效；更改设置后，朋友视角立即变化。

### US-F1：账号数据导出 / 删除（合规，PIPL）

> 作为用户，我想导出或删除我的数据。

**验收标准**
- 导出：一键导出我的关系数据（联系人 + 分组 + 标签），格式 CSV/JSON。
- 删除账号：确认后进入冷静期（D-F1），到期彻底删除所有云端数据。
- 删除后：我的关系数据不再用于任何匹配；我的化名从朋友的网络中移除。

**【需决策】D-F1：删除账号冷静期**
- 推荐默认：**确认删除后 30 天冷静期**（期间可撤销），到期彻底清除——与 GDPR/PIPL 的删除权兼容。
- 备选：立即删除（体验干净，但不可撤销）。

## 6. 跨端一致（US-G）

### US-G1：Web 看图

> 作为用户，我想在电脑网页上看到更大、更精美的关系图。

**验收标准**
- 同一账号登录 Web → 看到与 App 一致的关系图（更大画布 + 更精细交互）。
- **Web 不做通讯录导入**（决策 #01）；Web 上的修改实时同步到 App。
- 首次 Web 登录：二维码扫码（手机已登录）或手机号验证码。

## 7. 非功能需求（仅列出，详细文档另出）

- 性能：关系图 2000 联系人量级生成 ≤ 3s；页面加载 ≤ 2s。
- 隐私合规：PIPL（中国大陆）+ 通用隐私基线（数据导出 / 删除 / 最小化）。
- 安全：验证码防刷（D-A2）、通讯录数据加密传输与存储、账号绑定安全。
