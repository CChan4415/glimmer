## 1. 隐私合规（中国大陆 PIPL 为主）

> 注：面向大陆市场、收集通讯录第三方数据、且涉及云端存储——触发 PIPL 三条关键义务：① 单独同意（第九条）；② 数据跨境（第三十九条，仅当服务器在境外时触发）；③ 个人信息主体权利（第四十七条，查阅/更正/删除）。PIPL 是中国大陆现行法，违规处罚为上年营业额 5% 或 5000 万元（取高者）。

### 1.1 通讯录导入的"单独同意"

- **触发点**：用户点击"导入通讯录"。
- **要求**：必须在调起系统通讯录权限**之前**，弹出独立弹层，内容包含：
  - 收集目的："用于生成你的关系图，匹配'朋友的朋友'功能。"
  - 收集内容："姓名、电话号码（哈希存储）、通讯录分组。"
  - 存储方式："你的手机号不会以明文存入云端。"
  - 第三方说明："你的联系人如未注册，将向你朋友的朋友显示为化名（如'陈先生'）；已注册的联系人可按本人设置展示。"
  - 说明这不是系统通讯录权限弹窗（两者分开，先告知再调系统弹窗）。
- **要求**：拒绝后不影响 App 其他功能使用（不得因"拒绝"而限制基本使用——PIPL 第十六条）。
- **验收**：合规审核截屏（先告知弹窗 → 再系统权限弹窗）；拒绝后仍可手动添加联系人。

### 1.2 个人信息收集最小化

- **要求**：仅收集为实现第一版需的最少字段（PIPL 第六条）：
  - 必收集：手机号（账号主键）、通讯录联系人姓名、手机号（哈希上传）、通讯录分组。
  - **不收集**：定位、相册、麦克风、相机、剪切板、设备指纹（除非后续版本需要）。
- **验收**：代码审查 + App 权限列表审阅（仅通讯录一项敏感权限）。

### 1.3 隐私政策与用户协议

- **要求**：
  - App 启动后首次注册/登录前，必须弹层展示《隐私政策》（链接可点击），需"同意并继续"才进入注册。
  - 隐私政策内容至少覆盖：收集什么、为什么收集、存在哪、保留多久、与谁共享、用户权利、联系方式。
  - 隐私政策变更时推送通知 + 在 App 内公告（30 天前告知）。
- **验收**：合规评审；首次冷启动截图留存。

### 1.4 数据导出与删除

- **要求**（PIPL 第四十七条）：
  - **导出**：用户可一键导出其全部数据（联系人 + 分组 + 关系图配置），格式 **CSV**（跨端可读、处理简单）。从请求到导出文件完成 ≤ 72h（符合"合理期限内"要求）。
  - **删除账号**：用户可一键删除账号（确认后 30 天冷静期，期间可撤销）。到期后彻底删除：姓名、哈希、分组、关系链，不可恢复。
  - **删除联系人**：单个联系人删除即时生效、不可撤销（非账号）。
  - **拒绝删除例外**：法律义务保留期限除外（如诉讼留存），届时告知用户。
- **验收**：测试导出防数据不一致，测试删除后重新登录无残留数据。

## 2. 性能目标

### 2.1 关系图渲染

| 场景 | 约束 | 基线 |
| --- | --- | --- |
| 关系图首屏渲染（≤200 联系人） | ≤ 2s | 启动 App 到图可见 |
| 关系图首屏渲染（200–1000 联系人） | ≤ 4s | 最大首版预期量级 |
| 2 度节点展开 | ≤ 1s | 点节点到新节点可见 |
| 图交互（缩放/拖拽/拂动） | 60fps（用户感知无卡顿） | 50+ 个节点 |
| 聚合 / 过滤（>100 人提示筛选） | ≤ 1s | 筛选到结果切换 |

### 2.2 通用

| 场景 | 约束 | 基线 |
| --- | --- | --- |
| 首页加载（冷启动） | ≤ 3s | 登录到首页可见 |
| 页面间切换（热启动） | ≤ 0.5s | Tab 间跳转 |
| 验证码抵达（国内通道） | ≤ 10s | 95% 送达率 |
| 导入后应用启动（数据已缓存） | ≤ 2s | 热启动恢复 |

### 2.3 网络

| 场景 | 约束 |
| --- | --- |
| API 响应（登录 / 获取联系人 / 同步） | ≤ 2s（P95） |
| 离线消息（本地缓存） | 全部可离线查看已缓存的关系图 |
| 适配网络 | Wi-Fi / 4G / 5G；弱网下保可用（降级版），不白屏 |

## 3. 安全基线

### 3.1 身份与认证

| 项 | 要求 |
| --- | --- |
| 验证码 | 60s 重发间隔；错 5 次锁定 10 分钟；单日每号上限 20 条；不含可枚举的验证码 |
| token | 访问 token 过期 ≤ 7 天；刷新 token 过期 ≤ 30 天；退出登录立即失效所有 token |
| 微信 / Apple 绑定 | 绑定操作需当前已登录会话内完成；绑定本人手机的微信只能绑定该手机账号 |

### 3.2 传输与存储

| 项 | 要求 |
| --- | --- |
| 传输 | 全链路 HTTPS/TLS 1.2+；验证码和 token 不在 URL 参数传输 |
| 存储 | 明文手机号**仅本地存储** ≠ 服务端存哈希；所有本机数据加密（iOS Keychain / Android EncryptedSharedPrefs）；服务端哈希加盐存储（bcrypt/scrypt 或 HMAC-SHA256 加全局 salt） |
| 通讯录 | 上传的是手机号哈希 + 姓名 + 分组；原始明文手机号不在服务端日志、错误消息中打印 |

### 3.3 系统安全

| 项 | 要求 |
| --- | --- |
| HTTPS | 强制 HSTS（HTTP Strict Transport Security） |
| 速率限制 | API 端点节流（per IP + per user）：验证码/登录 ≤ 5 req/min；其他端点 ≤ 120 req/min |
| SQL 注入 | 使用 ORM + 参数化查询 |
| XSS | 移动端 WebView（若有）禁用 JS 注入；API 响应头 CSP、X-Content-Type-Options |

## 4. 数据治理

### 4.1 数据分类与保留

| 分类 | 字段 | 保留期 | 删除方式 |
| --- | --- | --- | --- |
| 账号主键 | 手机号（明文，本地） | 本地 = 删除 App 即丢失；服务端无 | 退出登录清本地 |
| 关系数据 | 联系人姓名、电话号码哈希值、分组 | 账号存活 + 30 天（冷静期） | 到期彻底删除 |
| 匹配中间数据 | 手机号哈希（匹配索引） | 账号存活 | 删除账号后 30 天清除 |
| token | 访问/刷新 token | 过期自动清除；退出登录立即 | 本地清除 |

### 4.2 访问控制

- 用户只读写自己账号下的数据（行级安全 RL 或应用层路由）。
- 管理员/运维：无权读取联系人姓名、手机号（明文/哈希均可分离存储，运维终端仅访问日志但不含 PII）。
- 日志：不含明文手机号、联系人姓名、关系链（仅 ID/时间戳）。

### 4.3 备份与恢复

- 数据库自动备份频率 ≥ 每日；备份加密。
- 备份保留期 ≤ 90 天（过期自动清除）。
- 恢复：RTO ≤ 4h，RPO ≤ 24h（[见 D-3 进一步定义](#5-决策记录本文档)）。

## 5. 模块化架构约束（技术）

> 决策 #08："效果不满意或找到更好方案时，能快速替换而不重构业务逻辑。"

### 5.1 三层独立接口

| 层 | 封装内容 | 替换触发 |
| --- | --- | --- |
| 渲染层 | 关系图渲染引擎（web） / 移动端图展示 | 换引擎、不满意视觉效果 |
| AI 层 | 标签订阅 / 事务 | 换模型、换 API |  
| 数据层 | 关系数据存储与查询 | 换数据库、换图引擎（从递归 CTE 迁 Neo4j 等） |

- **要求**：业务逻辑代码不直接调用具体引擎，通过接口访问；新引擎只需实现同一接口，替换时业务层不改。
- **第一版影响**：渲染层不是阻碍项（Web 引擎先行，换的是 Web 图库而非 App 核心逻辑，风险可控）。

## 6. 运维与监控（P1，[见 D-2](#5-决策记录本文档)）

第一版目标用户量小，不要求强 SLA 监控。最低：

- API 错误率超过 5% 时触发告警（服务端日志即可）。
- 关键端点健康检查：登录 / 同步 / 图渲染（ping 每 5 分钟）。
- 部署和备份策略在设计文档中细化。

## 附：P0 交互细节未覆盖的异常流（本文档收尾）

| 场景 | 行为 |
| --- | --- |
| 用户删除了手机里的通讯录联系人，该联系人已在 App 中有关系 | 保留为手动联系人（P0 交互 D-3 已确认） |
