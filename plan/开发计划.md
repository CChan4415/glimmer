# 开发计划与里程碑拆分 — Glimmer / 流萤（第一版）

> 状态：**初稿（待拍板）** · 2026-08-12
> 前置依据：全部 4 份需求文档 + 4 份设计文档 + 15 条产品决策

│ · Supabase 配置   │      │ · Web 关系图(React)  │      │ · 关系图 + 2 度展开   │      │ · TestFlight     │

**总预估**：约 7-10 周（单人兼职开发）。每周约 10-15 小时。时间线不冻结——实际进度在每阶段结束后修正。

## M2：核心 API + Web 看图（约 2-3 周）

### 目标

27 个 API 端点全部可用、Web 端关系图可访问、2 度发现查询跑通。

### 产出清单

| # | 产出 | 验收标准 |
| --- | --- | --- |
| 2.1 | **认证系统**：`POST /auth/send-code` / `verify` / `refresh` / `logout` | curl 发验证码 → redis/内存存 code → verify 返回 access_token |
| 2.2 | **阿里云 SMS 集成**：send-code 触发真实短信 | 手机收到验证码（SMS 签名 + 模板审核通过） |
| 2.3 | **JWT 中间件** + **依赖注入**：`get_current_user` | 带 `Authorization: Bearer <token>` 的请求解出 user_id |
| 2.4 | **通讯录 CRUD**：`POST /me/contacts/batch` + `GET` + `GET/:id` + `PUT/:id` + `DELETE/:id` + `POST /me/contacts` | 导入 100 条测试数据 → 列表返回正确（分页/筛选/排序）→ 编辑更新 → 删除消失 |
| 2.5 | **手机号哈希**：导入时 HMAC-SHA256 加密 + 存入 contacts.phone_hash | 同号码两次导入 → 同哈希值 |
| 2.6 | **2 度发现 Service**：`GET /me/network/first-degree` + `GET /me/network/second-degree/:contact_id` | 用测试数据（3 个注册用户互有联系人）跑通：A 展开 B 的 2 度 → 看到 C（化名），三层隐私开关分别关闭后结果正确 |
| 2.7 | **关系图数据 API**：`GET /me/graph` | 返回节点（1 度真名 + 2 度化名）+ 边 + 统计（分组 + 前 3 标签） |
| 2.8 | **隐私设置 API**：`GET/PUT /me/privacy` + `PUT /me/nickname` | 切换开关后 2 度查询结果即时变化 |
| 2.9 | **账号管理 API**：`GET /me/account` + `POST /me/export` + `DELETE /me/account` + `POST /me/account/restore` | 导出下载 CSV 含正确字段；删除后 30 天冷静期 |
| 2.10 | **预设标签 API**：`GET /tags/presets` | 返回 26 个预设标签 |
| 2.11 | **速率限制**：验证码 5 次/分钟 + API 120 次/分钟 | 超过限制返回 429 + Retry-After 头 |
| 2.12 | **Web 关系图**：React 项目骨架 + Cytoscape.js 力导向图 + 节点点击 + 2 度展开 + 统计面板 | 浏览器访问 `glimmer.app`（或 Railway 域名），登录（手机号验证码），看到自己的关系图，可缩放/拖拽/点击节点看化名/展开 2 度 |

### 不做的
- 不写移动端代码（M3）
- Web 不做编辑/删除/导入（仅看图，UI 架构 D-1）

### 【需决策，见 §5 D-2】

## M3：移动端 App（约 3-4 周）

### 目标

Flutter App 在 iOS 模拟器 + Android 模拟器上跑通完整用户旅程：注册 → 导入 → 生成图 → 看 2 度 → 编辑 → 隐私设置。

### 产出清单

| # | 产出 | 验收标准 |
| --- | --- | --- |
| 3.1 | **Flutter 项目骨架**：Riverpod + 路由 + API 客户端封装 + SecureStorage | `flutter run` 在模拟器启动，能看到三个 Tab 骨架 |
| 3.2 | **登录/注册流**：手机号输入 → 验证码 → 引导页（3 屏可跳过）→ 进入首页 | 新用户完整走完 P1→P2→P3；老用户 token 有效时冷启动直接进关系图 |
| 3.3 | **通讯录导入**：权限说明弹层 → 系统通讯录权限 → 读取+解析+去重+上传 → 完成页 | 权限拒绝不卡流程；1000 条测试通讯录 30s 内完成导入；结果与预期一致 |
| 3.4 | **关系图（Tab 1）**：graphview 力导向图 + 中心 = 我 + 1 度节点分组着色 + 一键展开全部 2 度 + 单节点展开 2 度 + 节点点击详情卡片（Botton Sheet） + 统计卡片 | 图交互不卡顿（≥200 节点）；一键展开正确显示所有已注册 1 度的 2 度；点 2 度节点显示化名 |
| 3.5 | **联系人列表（Tab 2）**：搜索栏（本地过滤）+ 分组 Tab 筛选 + 列表项点击进入详情 + 批量手动添加（表格式 P10） | 分组 Tab 切换正确；搜索实时过滤；批量添加 10 行提交成功 |
| 3.6 | **联系人编辑/删除**：详情卡片 → 编辑（全屏表单）+ 删除（二次确认） | 编辑保存后图和列表同步更新；删除后节点从图消失 |
| 3.7 | **我的（Tab 3）**：隐私设置（双开关 + 展示级别 + 昵称）+ 账号信息 + 数据导出 + 删除账号 | 开关切换后 Web 端 2 度视图即时变化；导出下载 CSV；删除账号进入 30 天冷静期 |
| 3.8 | **Apple 登录**：Apple Sign-In 按钮 → 授权 → 登录成功 | 模拟器/真机 Apple ID 授权后进入 App |
| 3.9 | **空态/引导态**：0 联系人空态 + 2 度门槛未达引导 + 3 度"即将推出"提示 + 网络异常重试 | 所有边界情况不白屏不崩溃 |

### 不做的
- 不做微信登录（后补）
- 不做推送（站内通知 M4 再加）
- 不做 3 度展开（第二版）

### 【需决策，见 §5 D-3】
